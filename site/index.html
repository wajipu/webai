GitHub 仓库 Releases 下载

01它解决什么问题

免费的网页 AI 没有公开 API,只有浏览器里的界面。webai 通过一个 Chrome 扩展桥接你的命令行和网页 AI:终端发消息,网页 AI 处理,回复取回终端。

复用你已登录的会话,不抓包、不逆向接口、不写 token —— 就像你自己在网页里打字。

02运行流程

一条消息从终端出发,走完整个链路后把结果带回

webai ask "…"命令行 / CLI
▼① 发送 {type:"ask", id, payload}
Rust 守护进程ws://127.0.0.1:8765 按 id 路由
▼② 转发给扩展(心跳保活)
Chrome 扩展 (MV3)找/开标签页 → 内容脚本按站点分发
▼③ execCommand('insertText') 注入输入框 → 点发送
网页版 AIchatgpt.com / grok.com / kimi.com / chatglm.cn
▲④ 轮询:停止按钮消失 + 回复连续 3 轮不变
提取回复 (Markdown)+ 会话 URL + 站点
▲⑤ {type:"ask_result", ok, data} 原路返回
终端打印结果--json 输出结构化 JSON

03约束注入(话题绑定)

本地 skills / 约束文件按话题绑定:首次初始化时注入一次,之后同话题自动跳过。

  • 状态存本地 ~/.webai/conversations.json + 内容指纹
  • 约束文件变了 → 指纹变化 → 自动重新注入
  • --reinit 强制重注入(聊久了/换模型后)

04快速开始

  1. 下载二进制
    curl -fsSL https://raw.githubusercontent.com/wajipu/webai/main/install.sh | bash
export PATH="$HOME/.webai/bin:$PATH"
  2. 启动守护进程 
    webai serve
  3. 加载 Chrome 扩展
    解压 webai-extension.zip → chrome://extensions → 开发者模式 → 加载已解压的扩展程序(图标变 ON)
  4. 浏览器里登录一次目标 AI 站点
  5. 提问 
    webai ask "用一句话解释 Rust 所有权"
webai ask --site kimi "你好"
webai ask --conversation https://chatgpt.com/c/xxx --system rules.md --skills ~/.claude/skills "开始干活"

06线协议(JSON over WebSocket)

→ { "type": "hello", "role": "cli" | "extension" }
→ { "type": "ask", "id": "uuid", "payload": { "message", "conversation?", "site?", "timeout_ms?" } }
← { "type": "ask_result", "id", "ok": true, "data": { "text", "url", "title", "site" } }
← { "type": "ask_result", "id", "ok": false, "error": { "code", "message" } }

错误码:NO_EXTENSION · BUSY · LOGIN_REQUIRED · SITE_DRIFT · TIMEOUT

07设计要点

问题方案
MV3 空闲 30s 回收 service workerchrome.alarms 定时 ping 保活
ProseMirror 等富文本不认直接赋值execCommand('insertText') 触发原生输入事件
AI"半句假完成"停止按钮消失 + 文本连续 3 轮稳定
站点改版选择器集中在 adapters/,每站一个文件
扩展无法监听端口扩展主动外连 daemon(127.0.0.1)
